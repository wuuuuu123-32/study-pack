# study-pack

> 把「课件（+ 作业题）」变成一套**能存下来**的学习材料——讲义、答疑册、复习卡。

听课件的速度跟不上、作业又催得紧时，最常见的做法是直接看答案——然后看不懂，因为缺最基础的那层概念。这个 skill 把整件事固化成一条流水线，产出三份互不污染的文件。

当前版本 **v0.5.5**，历次改动见 [CHANGELOG.md](CHANGELOG.md)（含每次发版要逐条过的**发布清单**）。

## 流程：文件 → 学习 → 答疑 → 成册

```
你：给我课件（+ 题目 + 题号）
        │
        ▼
我：建逐页索引 →（有题就裁单题图）→ 写出【讲义】并交付成文件（HTML + PDF）
        │
        ▼
你：打开讲义自己学      ← 学习发生在这里，不是在聊天框里
        │
        │  哪里看不懂
        ▼
你：回到对话里问
我：先把这条落盘进【答疑册】，再在这里回答
        │
        ▼
你：说一声「总结」
        │
        ▼
我：答疑册收尾 + 从里面归纳出【复习卡】
```

## 三份产物

| 产物 | 是什么 | 什么时候给 | 形态 |
|---|---|---|---|
| **讲义** | 逐题模式（有题目）：基础总讲 + 逐题「考什么 → 概念是什么 → 公式从哪来 → 怎么下手 → 解答」；知识讲义模式（只有课件）：按知识结构分节的整章讲解 | 开始学习前，一次给全 | **HTML + PDF**（PDF 必导） |
| **答疑册** | **你真正问过**的每一条问题：原话 + 回答要点 + 暴露的漏洞（你没提问就不建这个文件） | 边学边记，最后定稿 | Markdown |
| **复习卡** | 从答疑册归纳出的卡点 + 正解 + 一道自检题 | 你说「总结」时 | Markdown |

三份分开维护，互不污染。

## 两种模式

有没有作业题都能用，区别只在**讲义怎么组织**：

| 你的材料 | 走哪种模式 | 讲义长什么样 |
|---|---|---|
| 课件 **+** 作业题 | 逐题模式 | 基础总讲（整章一次）+ 逐题「考什么 → 概念是什么 → 公式从哪来 → 怎么下手 → 解答」 |
| **只有课件** | 知识讲义模式 | 按知识结构分节的整章讲解：全章地图 → 逐节（这一节要解决什么 / 核心概念 / 公式与来历 / 与相邻概念的区别 / 典型应用 / 容易错的地方）→ 全章小结（概念依赖图 + 公式表 + 易混对照表 + 自测问题） |

**没有作业题不是打折扣。** 知识讲义模式的要求反而更硬：

- **详略得当**——承重的概念（后面还要用的、最容易卡住的）展开讲透；历史背景、人名、纯代数中间步骤一句带过。
  一句话判据：**讲义是「讲清楚」用的，不是「讲完整」用的。**
- **透彻**——每个公式都有来历，每个概念都说清「它不是什么」，每个结论都标适用条件，关键处给出「遇到问题该用哪个公式」的判据。
- **按知识结构重组**——不按课件页码顺序照抄；讲义长度由知识点数量决定，不由课件页数决定。

答疑册和复习卡两种模式完全一样：学的时候照样提问、照样记账，说「总结」时照样成册。

## 运行前提：权限模式

讲义最后要导成 PDF，这一步走**浏览器无头打印**（`msedge --headless --print-to-pdf`）。
它需要 DSH 处于 **`danger-full-access`** 权限模式。在 `workspace-write` / `read-only` 下，
浏览器进程会直接崩掉：

```
ERROR:third_party\crashpad\crashpad\client\crashpad_client_win.cc:456] OpenProcess: 拒绝访问。 (0x5)
FATAL:mojo\public\cpp\platform\platform_channel.cc:187] Check failed: . : 拒绝访问。 (0x5)
ERROR:...crashpad_client_win.cc:144] crash server failed to launch, self-terminating
```

**这是沙箱的硬边界，不是参数没调对。** 实测三种 headless 模式、十来个开关
（`--no-sandbox` / `--no-zygote` / `--single-process` / `--disable-crash-reporter` / 改 `TEMP` …）
全部无效，提权重试也一样。同一台机器、同一条命令，只把权限模式从 `workspace-write`
换成 `danger-full-access`，就从"3 次全崩"变成"8 秒出片"——变量只有这一个。

| 权限模式 | 讲义 PDF | 怎么办 |
|---|---|---|
| `danger-full-access` | ✅ 8 秒出片，版式与 HTML 逐像素一致 | 正常走 |
| `workspace-write` / `read-only` | ❌ 浏览器必崩 | 在权限选择器里切到 `danger-full-access`；不切就走 LaTeX 备用路线（观感与 HTML 版不同） |

所以**开工前就会问你一句权限模式**。它是**整场会话的固定值**——等讲义写完才发现出不了片，
用户已经白等一两个小时。权限模式只有用户能改，agent 不能自己切，也不许换工具去绕沙箱。

## 设计上的几处刻意选择

这是它和"让 AI 把答案打一遍"的区别所在。

**1. 讲义是文件，不是聊天记录。**
能存、能打印、能带去教室；聊天记录会被上下文压缩吃掉，文件不会。
（第一个实战章节产出的是一份 17 页 PDF，公式用 MathJax 排版。）

**2. 讲义假设你完全没学过。**
禁用"复习 / 回顾 / 如你所知 / 显然"。新名词第一次出现要讲三件事——**是什么、为什么要它、它不是什么**；新物理量给**定义式 + 单位 + 是态函数还是过程量**。
热力学那份讲义一开头就是「读前必看」，把内能、功、热量、准静态过程、热容从头讲一遍，才进第一道题。

**3. 每个知识点都带来源页码。**
格式像这样：`来源：课件4 p.6–11（卡诺循环）`。
觉得我讲错了、或者想多看一点，直接翻原课件那一页——不用问"这是哪来的"。

**4. 答疑册连"你是怎么问的"一起记。**
每条固定四段：**我问的原话 / 回答要点 / 我暴露出的漏洞 / 关联**。
只记正确答案没用——复习时要看出"当时卡在哪儿"，靠的正是那句原话。

**5. 答疑先落盘，再回答。**
不是为了让用户早看到，而是因为对话上下文会被压缩，"回头一起整理"必然丢东西。
用户不需要管这件事，学完它自然就在那儿了。

**6. 复习卡是归纳，不是复制。**
同一类错误合并成一条，配一道自检题。复习时是在**做题**，不是在读清单。

**7. 该配图才配图。**
路径、绕向、面积、装置结构这类**空间 / 拓扑关系**，文字描述不可靠，必须画；
纯数值对比（比如"三种过程 ΔE 相同"）用表格，不画示意图凑数。

**8. 符号约定全文唯一。**
热力学里"气体对外做功为正"和"外界做功为正"是两套相反约定。选定一套，全文执行，中途不换。

**9. PDF 导出后必须亲眼看过，才算做完。**
`pdfinfo` 说"50 页"、`pdftotext` 能抽出文字，都只证明东西进去了，不证明版式没坏——
有一次正文冲出页面右边缘被截断、边框盒全塌，而这些数值检查全部通过。
所以规矩是：抽 3–5 页渲染成 PNG，**打开图看**。这条和导出流程一起写在 `references/export.md`。

**10. 答疑册只记你真正问过的问题。**
你没提问就**不建这个文件**。把菜单选项、讲义里的知识点、或 agent 自己想到的"常见疑问"
写成「我问的（原话）」，属于**伪造学习记录**——比漏记严重得多。
（这条是 agent 自己犯过之后加的：在用户从未提问的情况下建了答疑册并替用户编了 3 条问答。）

**11. 数学式里不许出现裸的 `<` `>` `&`。**
`Y_{A<B}` 里的 `<` 会被浏览器当成标签开头，一路吞到下一个 `>`：公式**在浏览器里就少一截**，
被吃掉的 `</div>` 让整块内容再也不闭合，转 PDF 时后面所有插图报 `Not in outer par mode`。
一律写 `&lt;` `&gt;` `&amp;`，并以 `scripts/check_html_math.py` 当门禁（退出码必须为 0）。

**12. 讲义在屏幕上居中窄栏，不铺满窗口。**
1600px 宽的显示器上满宽正文一行近 100 字，眼睛跟不住。固定 `body{max-width:900px; margin:26px auto}`，
四周浅灰底、白色卡片；打印时用 `@media print` 把宽度和内边距撤掉，交给 `@page`。
反过来说，`max-width:100%` 等于没设宽度，`margin:0 auto` 随之失效 —— 两份习题讲义就是这么铺满整屏的。
可复制片段见 `references/conventions.md` §1.4。

## 怎么开始

### 第一步：把材料给我

**课件是必需项**，**题目可选**：有作业题就按题讲，没有就讲成一整章知识讲义。有题的话，请告诉我**题号**。

**A. 电子课件 + 电子作业题（最省事）**

> 课件：`第10章 热力学基础1.pdf` … `6.pdf`
> 作业：`习题10.pdf`，做第 4、5、7、8、9、10、13、15、17、19、21 题

**B. 题目在纸质书 / 屏幕上 / 老师发的图里**

直接**拍照发给我**。一张图里几道题都行，但**题号要拍清楚**——糊了我就只能猜是第几题，宁可你再补一张。

**C. 题目在电子课本里**

给课本文件 + 题号（"第 253 页 习题 10-4 到 10-9"这样也行）。

**D. 只有课件，没有作业题**

只给课件就行。我会把它讲成一整章的知识讲义（按知识结构分节，不是按页摘抄），你照样边学边问。

课件是电子版还是扫描版都行，我自己判断：有文字层就搜关键词定位，扫描版就渲染成图再读。

### 第二步：等讲义，打开它学

讲义落成 **HTML + PDF** 给你。**学习发生在文件里**——翻它、在上面画、打印出来都行。
HTML 是"源"，PDF 是方便打印和带走的副本；完整模式下两者版式一致，受限模式下 PDF 版面会不同，但内容完整。

### 第三步：有不懂的，回到对话里问

任何地方卡住就直接问，不用管学到哪了。我会先把这条记进答疑册，再在这里回答。
（你没问过的问题不会被写进去。）

### 第四步：说一声"总结"

我把答疑册收尾，并从里面归纳出复习卡。
之后你随时可以让我照课件目录通检一遍，看讲义漏讲了哪些知识点。

## 三条原则

- **不预设读者学过**：禁用"复习 / 回顾 / 如你所知 / 显然"。
- **可回溯 > 堆砌**：每个知识点都标来源文件与页码，漏了也能自己查回去。
- **分离维护**：讲义、答疑册、复习卡各是各的文件。

## 适用范围与边界

- 适用：以**课件**为依据的学习材料生产（有作业题更好，没有也能讲成整章知识讲义）；材料来自哪里不限（电子文件、扫描件、纸质拍照、屏幕截图都可以）。
- **只有课件、没有题目**时：走知识讲义模式，产出一份按知识结构组织的整章讲解（不是"缩水版总讲"，要求见上面「两种模式」）。
- 不适用：没有依据的纯写作；纯查资料；纯排版美化。
- 本 skill **不含学科知识**。学科专项工具（如图生成脚本）应放在各自项目的 examples 里，不要写进本体——否则会把某个学科的特例误当成通用规则。

## 安装

**放进 DSH 的 skills 目录时，它必须是链接，不能是复制。**

```powershell
# Windows：junction（免管理员权限）
New-Item -ItemType Junction -Path "$env:USERPROFILE\.dsh\skills\study-pack" -Target "<你克隆到的路径>"
```

把 `<>` 里的内容换成你自己的路径。

```bash
# Linux / macOS
ln -s /path/to/study-pack ~/.dsh/skills/study-pack
```

**为什么不能用复制**：复制出来的那份会**永久停在被复制的那一刻**。它看上去和真身一模一样——
没有报错、没有警告，只有"我明明改了怎么没生效"的困惑。

这个坑真实发生过：一份 v0.1.0 的副本在 skills 目录里躺了很久，期间仓库已经发到 v0.4.0，
而每一场会话加载的仍是 v0.1.0——新版里的「知识讲义模式」「详略得当判据」「PDF 导出流程」
从未被读过，只能靠对话现场重新推。**链接则永远指向当前版本。**

装完核对一次：

```powershell
Get-ChildItem "$env:USERPROFILE\.dsh\skills"   # 要看见 study-pack
(Get-Content "$env:USERPROFILE\.dsh\skills\study-pack\package.json" | Select-String '"version"').Line
```

```bash
ls -la ~/.dsh/skills/                                        # 要看见 study-pack -> /path/to/study-pack
grep '"version"' ~/.dsh/skills/study-pack/package.json       # 版本应与仓库一致
```

已经误建了复制的：改名备份后重新建链接即可。Windows 上 `New-Item -ItemType SymbolicLink`
需要管理员权限，`Junction` 不需要。
