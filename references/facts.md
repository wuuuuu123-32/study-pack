# 事实一致性：同一句话里对的东西，可能把错的东西包住

> 这份文件回答一个问题：**为什么「同一份文档里同一个器件被说成两种相反属性」这种错误，
> 靠认真读、靠渲染检查、靠会审都抓不住，必须单独上一道文本比对。**

---

## 1. 事故原文（2026-11-27，作业四讲义）

同一份 38 页讲义里：

| 位置 | 原文 | 对错 |
|---|---|---|
| 2.5 节表「清零端同步还是异步」 | `74LS160 / 161 / 162` → **异步清零** | ✗ 162 是同步 |
| 2.6 节表「四颗计数器芯片逐脚讲」 | `74LS162` → **同步** | ✓ |
| 2.6 节引脚行 | `160/161/162 立刻清；163 等 CP` | ✗ |
| 2.11 节符号速查 | `160/161/162 异步、163 同步` | ✗ |

用户是拿两张截图对比着问出来的：「你这不对吧，74ls162 图一说异步清零，图二说同步清零」。

正确答案：**160/161 异步清零，162/163 同步清零**（课件13 p.3 总表、p.15 功能表）。
160/162 都是十进制、161/163 都是十六进制；160/161 异步、162/163 同步 ——
两个维度正交，**编号的相邻关系与任何一维都不对应**。按 160→161→162 的顺序回忆，
很容易把「相邻」读成「同类」。

## 2. 为什么这不是「粗心」

把它归成粗心，下次还会犯。真实的成因有四层，每一层都独立成立：

**① 编号不带语义，但人脑按顺序补语义。**
四个型号挂着 2×2 的正交属性。逐项表逼你一行一行看，不会出错；
一旦压成「160/161/162」这种归类写法，人脑就用「它们挨着，应该是一类」去填空白。

**② 换输出格式时，列表被「重新生成」而不是「推导」。**
逐项表是逐个写出来的（写的时候在想每一颗），斜杠归类句是一次成型的（写的时候在想「这一组的共同点」）。
重新生成有概率错，从已写对的表里抄不会错。所以**错误全部集中在归类句，逐项表一次都没错** ——
这不是巧合，是生成方式不同。

**③ 错误被正确元素包着。**
「160/161/162 异步」里三个成员有两个是对的。句子通顺、术语准确、没有语法破绽，
任何「读一遍看看有没有问题」的检查都会滑过去。

**④ 已有的检查手段结构性看不见它。**
- `check_html_math.py` 查的是渲染语法（裸 `<` `>`），不看内容真假；
- `read_image` 查的是版式（裁没裁、公式渲没渲），不看数字对不对；
- 会审看的是「机制有没有漏洞」，不是「162 到底是哪个」。

而这两张表在 PDF 里隔了 5 页 —— 目视核对永远不会把它们并排放。

## 3. 三条判据（可执行，不是「要细心」）

### ① 归类陈述必须由逐项表推导

写「X / Y / Z 都是 ……」之前，回到同一份文档里那张**一行一颗**的表，把成员逐个抄下来。
成员列表不是回忆出来的，是抄出来的。没有那张表就先写表。

判据是可数的：**归类句里的每一个型号，都能在文档某张逐项表里找到同名的一行。**

### ② 落盘前跑一次文本对账

```bash
python scripts/check_facts.py <讲义.html>
# 退出码 0 = 同一实体没有互斥陈述；1 = 有冲突，按提示人工裁决
```

它做的事：把正文切成**分句**，识别全文出现过的实体（`74LS162`、`CC4017`、`Fe2+`、`R1`），
对每条属性轴（同步/异步、高有效/低有效、上升沿/下降沿、Mealy/Moore……）
把同一实体的所有出现分句按词分组并排 —— 不同分句各执一词就报。

输出直接给并排证据，例如：

```
▶ 74LS162　属性轴「清零方式（同步 / 异步）」
  「同步」5 处：
    [讲义.html · 2.6 四颗计数器芯片逐脚讲] 74LS162  十进制（模 10）  8421BCD 码  同步  同步
    [讲义.html · 2.11 全篇符号速查表] 162/163 同步
  「异步」1 处：
    [讲义.html · 2.5 清零端同步还是异步] 74LS160 / 161 / 162  异步清零
  → 人工裁决：确认哪一个对，改掉另一边
```

它自己也有回归测试：`python scripts/test_check_facts.py` → 必须「✅ 八例全部通过」，
其中第一例就是这次事故的 HTML 复现。**改匹配逻辑后必须重跑** ——
一个永远返回 0 的检查脚本，看起来和正常的一模一样。

### ③ 版式核对与事实核对分开

| 检查 | 能证明 | 不能证明 |
|---|---|---|
| `pdftoppm` + `read_image` | 没被裁掉、没乱码、公式渲染了、分页没断表 | 数字对不对、型号对不对 |
| `check_html_math.py` | 数学区没有裸 `<` `>`，渲染不会吞标签 | 内容真假 |
| `check_facts.py` | 同一实体没有被说成两种相反属性 | 单点陈述本身错（比如整份文档一致地写错） |

三者是三个维度。**任何一道都替代不了另一道**，尤其不能用「我看过渲染了」当事实核对。

## 4. 它的能力边界（别把它当「事实正确性证明」）

**能抓**：同一实体在不同分句被说成互斥属性（这次的 162、以及任何「一个器件两种清零方式」）。

**抓不到**：
- 全文一致地写错（所有句子都说 162 是异步）—— 那需要和课件原文比对，脚本不知道真值；
- 单一陈述错但没别处矛盾（「R1 = 7.22 kΩ」算错）—— 要靠自己验算；
- 数值型事实（页码、阻值、状态序列）—— 不在属性轴覆盖范围。

所以它是**交叉验证**，不是**真理来源**。真值永远来自课件原文那一页。

## 5. 去噪规则（拿真实讲义调出来的）

只做「实体 + 属性词共现」时，38 页讲义报出 **3 处，全部是假阳性**：

| 假阳性 | 原句 | 为什么不该报 | 规则 |
|---|---|---|---|
| 一句多实体 | 「74LS160 十进制、74LS161 十六进制、74LS163 十六进制带**同步清零**」 | 「同步」属于 163，不属于 160/161 | 先切**分句**（按「，、；：——」），只在分句内判断 |
| 属性词被别的宾语领走 | 「161 的**置数**是同步的」 | 说的是置数同步，不是清零同步 | 轴声明 `exclude`（清零轴排除「置数/装载/LOAD」） |
| 否定句 | 「而 290 **没有**同步清零端」 | 词出现，语义相反 | 词前 9 字内有「没有/不是/并非/不存在/不能/不采用」就跳过 |

**表格必须按行处理**：`</td>` 后面不能断句，否则「74LS162」与「同步」被拆成两句，
属性词那半句只有两个字，会在短句过滤里被丢掉 —— 这正好把要抓的那一行漏掉。

## 6. 换科目怎么配轴

`--axes` 传一个 JSON：

```json
[
  {"name": "氧化性", "pair": ["氧化", "还原"], "exclude": ["催化"]},
  {"name": "导电类型", "pair": ["N 型", "P 型"], "exclude": []}
]
```

配轴要点：
- **只放真正互斥的两组词**。置位/复位、加法/减法这种在同一句里天然成对的，别进默认表；
- 轴上两个词若一个是另一个的子串（高有效 ⊂ 高电平有效），脚本会按长词优先算，但分开配两条轴更清楚；
- 实体识别默认抓两类：**带前缀的型号**（`74LS162`、`CC4017`）与**元素/元件标号**（`Fe2+`、`R1`、`C2`）。
  换到没有这类标号的科目（纯概念课），这道检查就用处不大 —— 别硬套。

## 7. 一句话

**能被同一份文档自相矛盾抓出来的错，都值得自动抓一次** ——
因为人眼在同一页里比对两张相隔 5 页的表，是做不到的。
