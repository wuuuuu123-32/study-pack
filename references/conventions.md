# 格式规格

## 1. 讲义

文件：out/<章节名> 讲解.html（或 .md），同时导出 PDF 供交付。

讲义有两种模式，按**有没有题目**选：

| 模式 | 什么时候用 | 组织方式 |
|---|---|---|
| 逐题模式 | 有作业题 | 基础总讲（整章只写一次）+ 逐题 |
| 知识讲义模式 | 只有课件、没有题目 | 按知识结构分节，一路讲完 |

### 1.1 逐题模式骨架

    # <章节名> 习题<编号> 讲解
    ## 读前必看：把本章基础从头讲一遍
       （分小节：概念 → 公式 → 表格 → 常见陷阱；每小节末尾标来源）
    ## <题号> <题目名>
       ### 这题考什么
       ### 概念是什么
       ### 公式从哪来
       ### 怎么下手
       ### 解答
       （末尾标来源）

"读前必看"是**整章的公共基础**，只写一次；各题只引用它，不重复讲。
但**引用时必须一句话点出用的是哪一条**，不许写"见前面"。

### 1.2 知识讲义模式骨架

    # <章节名> 知识讲义

    ## 这一章在讲什么
       （全章地图：核心问题是什么、有几个关键概念、它们之间怎么依赖；3–6 句）
    ## 读前必看：需要的预备知识
       （本章要用、但不属于本章的基础：符号、数学工具、上一章的结论；没有就整节删掉）
    ## <N.1 小节名>
       ### 这一节要解决的问题
       ### 核心概念 / 量
       ### 公式与来历
       ### 与相邻概念的区别
       ### 典型应用
       ### 容易错的地方
       （每节末尾标来源）
    ## …（逐节）
    ## 全章小结
       ### 概念依赖图（谁用到谁）
       ### 公式表（每条都带适用条件）
       ### 容易混淆的对照表
       ### 自测问题（只给题目与来源页码）

分节规则：

- **按知识结构分节，不按课件页码顺序照抄。** 一节对应一个知识点或一个要解决的问题，不对应一页课件；
  课件里跨页讲的同一件事要合并，同一页里讲的不同概念要拆开。页码只用于标来源。
- 讲义长度由**知识点数量**决定，不由课件页数决定。目标：没有一处需要读者回头翻课件才能看懂。

写作要求（这是"知识讲义"与"把课件摘一遍"的分界）：

- **详略得当。**
  详写三个信号：①后面的内容会用到它（承重概念：把定义讲透、给典型值）②读者最容易在这里卡住（反直觉的结论、容易混的概念对）③课件给了推导但跳了步。
  略写三个信号：①纯历史背景、人名、装置照片 ②长推导里的纯代数中间步骤（写"把 X 代入整理得"，直接给结论）③只出现一次、后续不再用的细节（给定义 + 出处即可）。
  一句话判据：**讲义是"讲清楚"用的，不是"讲完整"用的。** 宁可少讲一个次要细节，不能把一个承重概念压成一句话。
- **透彻。** 四条自检：
  ①每个公式都有来历——不是"记住这个式子"，而是它由哪个定义/定律推来、为什么长这样；
  ②每个概念都说了"它不是什么"——正确定义 + 一个常见误解；
  ③每个结论都标了适用条件——什么前提下成立，超出范围会怎样；
  ④关键处给出判据——遇到问题怎么判断该用哪个公式、哪个过程（这是"看懂了"和"会用"的分界）。
- **收尾的自测问题**只列题目与来源页码，答案不写进讲义——留给学习者自己算；要答案就回对话里问，答案进答疑册。

### 1.3 来源标注

统一成一行，放在每个知识小节末尾、每道题解答末尾：

    来源：<短名> p.<起>–<止>（<小节名>）

- 用**短名**（如"课件2"），并在讲义开头给一张**对照表**把短名映射到真实文件名与页数。
- 页码用**原文件的页码**，不是 PDF 页号——两者若不同，在对照表里注明偏移。

### 1.4 排版与导出

讲义以 **HTML 为源、PDF 为交付**。两条内容是硬约束：

- **数学式里绝不能出现裸的 `<` `>` `&`**（如 `Y_{A<B}`）。浏览器和 pandoc 都会把它当成标签开头，
  一直吞到下一个 `>`（通常就是 `</div>` 的 `>`）：公式后半段在浏览器里**直接消失**，
  div 从此不闭合，转 PDF 时后面所有图报 `! LaTeX Error: Not in outer par mode.`。
  一律写 `&lt;` `&gt;` `&amp;`；写完跑 `python scripts/check_html_math.py <讲义.html>`，
  **0 处可疑才算过**（退出码 0）。
- 每个 `<div class="…">` 必须闭合；表格给列宽（`<colgroup><col style="width:N%">`）。

排版本身：

- ❗**屏幕阅读用居中窄栏，打印才交回满宽。** 讲义是给人在电脑上读的，1600px 宽的屏上满宽正文一行近 100 字，
  跟不住。抄这段，别改：

  ```css
  html { background: #eef0f3; }
  body { box-sizing: border-box; max-width: 900px; margin: 26px auto;
         padding: 30px 38px 64px; background: #fff;
         box-shadow: 0 0 18px rgba(0,0,0,.08); }
  @media print {
    html { background: #fff; }
    body { max-width: none; margin: 0; padding: 0; box-shadow: none; background: #fff; }
  }
  ```

  `box-sizing: border-box` 不是可有可无：默认 `content-box` 下 `max-width: 900px` + 左右各 38px 内边距，
  卡片的**外宽其实是 976px**，跟「900px 窄栏」这个说法对不上，容易在下一份讲义里把数字越调越乱。

  三个坑：① **不要写 `max-width: 100%`**，那等于没设宽度，`margin: 0 auto` 什么都不做，正文直接铺满整屏
  （2026-10-18 的真实事故，用户看了两次才提）；② **`@media print` 里必须把 `max-width`/`margin`/`padding`/
  `box-shadow`/背景全部撤掉**，否则 PDF 会在 `@page` 的页边之外再缩进一层，或把屏幕用的阴影、灰底带进纸面；
  ③ **不要拿「PDF 页数没变」当通过判据**：页数是离散的粗粒度结果，重排了几行但没跨页，页数照样不变；
  反过来字体或内容一变，版式没坏页数也可能变。页数只用来发现「明显崩了」，真正的核对仍是
  `references/export.md` 里那条——抽 3–5 页渲染成 PNG 亲眼看：内容是否铺满 `@page` 内容区、有没有阴影或灰底、
  表格与正文有没有越过页边。
- 表格与"提示框"设 `break-inside: avoid`，避免被跨页切断。
- 允许长段落跨页（否则会留大片空白）。
- 数学公式用 MathJax **本地副本**（`mathjax/tex-svg.js`），不依赖 CDN。
- `@page{size:A4; margin:16mm 14mm}`。

**导出与核对的完整流程**（两条路径、可复制命令、权限前提、核对清单、写 HTML 时的坑）
见 [`export.md`](export.md)。三条不许省的：

1. 先看运行时上下文里的 `Current DSH file policy` —— 受限（`workspace-write`/`read-only`）时
   浏览器无头打印**必然崩**，要先请用户在权限选择器里切到 `danger-full-access`。
2. **PDF 必须导出**（只交 HTML 不算交付）。
3. 导出后抽 3–5 页渲染成 PNG，**用 `read_image` 亲眼看过**。`pdfinfo` 的页数、`pdftotext` 抽到文字
   这类数值自检**不算**核对 —— 历史上就是把版式全坏的 PDF 当成成功交出去的。

## 2. 答疑册

文件：<章节名> 答疑册.md，与讲义同目录、**独立文件**。

❗**没有真实提问就不建这个文件。** 它是"边学边写"的流水账，不是开工时该产出的空册；
用户没问过问题，本册就不存在。**更不许为了"三件套齐全"替用户编问答**——
把菜单选项、讲义知识点、你自己想到的疑问写成「**我问的**（原话）」，等于伪造用户的学习记录。

文件头必须写死规则：

    # 答疑册

    > 规则：每回答一次与讲义相关的疑问（不限于题目），先把这一条追加到本册，再在对话里讲。
    > 本册与讲义分开维护。

每条：

    ## <序号>. <短标题>（<题号>）

    **我问的**（原话）：<用户原话，不要改写>

    **回答要点**：
    - …

    **暴露的漏洞**：<哪里没懂 / 讲义哪里没讲清>

**原话一定要保留**——改写就丢掉了"当时是怎么错的"这条最有价值的信息。

## 3. 复习卡

文件：<章节名> 复习卡.md

每条：

    ## <卡点>
    **正确理解**：…
    **自检**：<一道能立刻验证的小题>

要**归纳**：同一类错误合并，按主题而非时间排序。

自检题从哪来：逐题模式用原题的变式；知识讲义模式没有现成题目，就针对这个卡点**现编一道小题**（三行以内能算完，答案附在后面）。

## 4. 目录与命名

- 科目用英文短名（physics / chemistry / math），章节用 ch10 这类。
- 目录用英文（便于脚本），交付文件名用中文全称（便于用户辨认）。

## 5. 唯一真源

- data/ 下的文件是唯一真源，out/ 里的交付物由它生成。
- **若规模小，不要强行拆两份**：答疑册本身就是唯一真源，直接维护它即可。
  只有当真源需要被多个交付物引用时，才拆出 data/。

## 6. 交付前自查

- [ ] 有没有漏题（对着题号清单逐个勾；只有课件时跳过这条）
- [ ] 每个知识点、每道题有没有来源
- [ ] 新名词、新物理量有没有解释
- [ ] 有没有"复习"式措辞
- [ ] `python scripts/check_html_math.py <讲义.html>` 退出码为 0（数学区无裸 `<`）
- [ ] 讲义 HTML 已产出，且 PDF 也已导出（`ls -l` 看得到非零字节）
- [ ] PDF 抽了 3–5 页渲染成 PNG 并**用 `read_image` 真的看过**（公式、表格、插图、分页、末页）
- [ ] 与 HTML 对照过第 1 页版式（详见 [`export.md`](export.md)）
- [ ] （知识讲义模式）是不是按课件页码顺序照抄了？应该按知识结构重组
- [ ] （知识讲义模式）承重概念有没有被压成一句话？背景介绍有没有写得太长？
