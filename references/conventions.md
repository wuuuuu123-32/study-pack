# 格式规格

## 1. 讲义

文件：out/<章节名> 讲解.html（或 .md），同时导出 PDF 供交付。

### 1.1 骨架

    # <章节名> 习题<编号> 讲解
    ## 读前必看：把本章基础从头讲一遍
       （分小节：概念 → 公式 → 表格 → 常见陷阱；每小节末尾标来源）
    ## <题号> <题目名>
       ### 这题考什么
       ### 概念是什么
       ### 公式从哪来
       ### 怎么下手
       ### 解答
       （末尾标来源）

"读前必看"是**整章的公共基础**，只写一次；各题只引用它，不重复讲。
但**引用时必须一句话点出用的是哪一条**，不许写"见前面"。

### 1.2 来源标注

统一成一行，放在每个知识小节末尾、每道题解答末尾：

    来源：<短名> p.<起>–<止>（<小节名>）

- 用**短名**（如"课件2"），并在讲义开头给一张**对照表**把短名映射到真实文件名与页数。
- 页码用**原文件的页码**，不是 PDF 页号——两者若不同，在对照表里注明偏移。

### 1.3 排版要点

- 表格与"提示框"要设 break-inside: avoid，避免被跨页切断。
- 允许长段落跨页（否则会留大片空白）。
- 数学公式用 MathJax，**本地副本**，不依赖 CDN。
- 导出后**必须渲染成图核对**（页数、公式、表格是否正常）。

## 2. 答疑册

文件：<章节名> 答疑册.md，与讲义同目录、**独立文件**。

文件头必须写死规则：

    # 答疑册

    > 规则：每回答一次题目相关疑问，先把这一条追加到本册，再在对话里讲。
    > 本册与讲义分开维护。

每条：

    ## <序号>. <短标题>（<题号>）

    **我问的**（原话）：<用户原话，不要改写>

    **回答要点**：
    - …

    **暴露的漏洞**：<哪里没懂 / 讲义哪里没讲清>

**原话一定要保留**——改写就丢掉了"当时是怎么错的"这条最有价值的信息。

## 3. 复习卡

文件：<章节名> 复习卡.md

每条：

    ## <卡点>
    **正确理解**：…
    **自检**：<一道能立刻验证的小题>

要**归纳**：同一类错误合并，按主题而非时间排序。

## 4. 目录与命名

- 科目用英文短名（physics / chemistry / math），章节用 ch10 这类。
- 目录用英文（便于脚本），交付文件名用中文全称（便于用户辨认）。

## 5. 唯一真源

- data/ 下的文件是唯一真源，out/ 里的交付物由它生成。
- **若规模小，不要强行拆两份**：答疑册本身就是唯一真源，直接维护它即可。
  只有当真源需要被多个交付物引用时，才拆出 data/。

## 6. 交付前自查

- [ ] 有没有漏题（对着题号清单逐个勾）
- [ ] 每个知识点、每道题有没有来源
- [ ] 新名词、新物理量有没有解释
- [ ] 有没有"复习"式措辞
- [ ] PDF 是否已渲染核对
