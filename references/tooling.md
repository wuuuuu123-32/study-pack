# 开工前的工具清点

> 这一步解决的不是"怎么用工具"，而是**"手上到底有什么"**。

## 为什么要有它

本 skill 里的规则绝大多数是「遇到情况 X 就做 Y」。但还有一类失败不属于这一类：

- **装了却忘了用。** 本机有 `office-pptx` 这个 skill，我却自己写了个 4.3 KB 的脚本去解 PPTX 的 zip 和 XML，
  因为"想不起来还有它"。
- **缺了却不说。** 画电路图的 `schemdraw` 没装，于是手写内联 SVG、手算每个引脚坐标，
  改了两轮还压字——正确做法是开工前就说"这个没装，要不要装"。
- **降级了却瞒着。** 少了目视核对的那一环，交出去的 PDF 版式是坏的，而所有数值自检都通过。

这三件事有同一个根源：**"我有什么工具"是个靠回忆的问题，而回忆不可靠**。
所以把它做成一次**真实的探测**（查 PATH、查 `import`、查目录），输出一张表，让缺口看得见、说得出口。

## 什么时候跑

**在 §零 确认材料形态的同一步，写任何内容之前。**

```bash
python scripts/check_tooling.py                        # 清点全部
python scripts/check_tooling.py --need schemdraw,PIL   # 声明这次必须有的能力，缺了 exit 1
python scripts/check_tooling.py --quiet                # 只输出缺口与结论
```

`--need` 填**这次任务真正会依赖**的那几项，别把整张表都填进去——填满了等于没填。

## 输出怎么读

三段：能力表（✓/✗ + 真实路径）、本地资源（MathJax 副本等）、已安装 skill。

有两处必须看：

1. **这次要用的那几项是不是 ✓。** 缺了就往下一步走。
2. **「已安装 skill」里有没有 `（复制，会漂移）`。** 有就顺嘴提醒用户一句——
   复制出来的副本会永久停在被复制的那一刻，看着却和真身一模一样。
   （Windows 上 `os.path.islink` 认不出 junction，脚本里已按 reparse point 判断。）

## 缺口怎么处理（三步，一步都不许跳）

1. **判断这项这次到底用不用得上。** 用不上就不提，别把清点变成噪音。
2. **用得上就当场说清四件事**：缺什么、会影响什么、装它的命令、不装的降级方案。
3. **等用户决定。** 安装属于「要先问」那一类——**不许自己装**；
   同时**不许瞒着缺口默默降级交付**（先干活、事后才说"这个我做不到"是最差的一种）。

### 话术模板

> 开工前先报个工具情况：`schemdraw`（画电路图用的）这台机器没装，
> 于是电路图得手写 SVG、坐标全靠手算，改起来慢也容易压字。
> 装它一行：`pip install schemdraw`；不装我就手写，但每张图都会渲染出来给你确认。
> 你定。

不装的时候要记住后半句：**降级方案必须带兜底**（手写 SVG → 必须渲染成图人工确认），
否则"降级"就变成了"糊弄"。

## 能力表（通用清单，换科目不用改）

| 能力 | 什么时候是必需的 | 缺了怎么办 |
|---|---|---|
| `pdftoppm` / `pdftocairo` | **只要要目视核对 PDF** | 装 TeX Live，或 `pip install pymupdf` 改用 `fitz` 渲染 |
| `pdftotext` | 核对正文/公式是否真的进了 PDF | pypdf / pymupdf 抽文本 |
| `pdfinfo` | 页数、页面尺寸（判断 A4 还是 Letter） | pypdf 读 `/MediaBox` |
| 浏览器（Edge / Chrome） | 讲义出 PDF（首选出片路线） | pandoc + xelatex，**但要告诉用户观感不同** |
| `pandoc` + `xelatex` | 浏览器不可用时的备用路线 | 只能走浏览器 |
| `PIL` | 裁图、拼 contact sheet、读手写照片 | 很多核对做不了，要提前说 |
| `matplotlib` | 函数图、曲线、坐标图 | 手写 SVG |
| `schemdraw` | **电路图、门电路**（声明式，不用手算坐标） | 手写内联 SVG，且必须渲染成图人工看 |
| `graphviz` | 流程图、依赖图、状态机 | 手写 SVG 或 mermaid |
| `python-pptx` / `python-docx` / `openpyxl` | 读课件原文（PPT / Word / Excel） | 解 zip + `xml.etree`（啰嗦但可行） |
| `pypdf` / `pymupdf` | 合并、拆页、读元数据 | 命令行 poppler 工具 |
| 本地 MathJax 副本 | 讲义公式（HTML 侧） | 从任意已有讲义目录拷一份 `tex-svg.js` |
| `node` / `git` | 发布、调 API、版本管理 | 一般都有 |

## 换科目时怎么扩表

学科专项能力（化学结构式、五线谱、地图……）**追加到这张表**，不要改判据。
新增一项要同时满足两条：

- **有明确的探测方式**（一条命令、一个 `import`、一个目录）——探不出来的就别写进来
- **缺了会显著影响质量**（不是"有了更方便"）

反过来，不要往表里塞抽象能力（"审美""推理"）。它们探不出来，写进来只会变成一句空话。

## 别把这一步做成形式主义

**反例**：跑一遍脚本，把表贴出来，然后什么都不改，接着按老办法干。

**判据（可数）**：表里每一个 ✗、且这次任务用得上的能力，必须在本次对话里**出现过一次明确的处置决定**
——装 / 不装（附降级方案）/ 换一个等价工具。三者之一即可，但不能没有。
